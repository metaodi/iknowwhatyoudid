# Checklist: Example Feature

> Template (optional). Use this to define acceptance criteria and quality
> gates for the feature before it is considered done.

## Acceptance Criteria

- [ ] Behavior matches every requirement listed in `spec.md`.
- [ ] No out-of-scope behavior was implemented.

## Quality Gates

- [ ] Tests added/updated and passing.
- [ ] Linting passes.
- [ ] Documentation updated if user-facing behavior changed.
- [ ] Implementation respects the project constitution
      (`.specify/memory/constitution.md`), e.g. local-first, no telemetry.
